# Production candidate and evidence path

`FounderFundedMining` inherits `FinancierMiningWithMarket`, `FinancierMiningWithSettlement` and `FinancierMining`. It fixes canonical FINCR runtime/supply, 400M reserve and the approved auction parameters. It creates `SeatOwnerAgentRounds` and `PermanentV4Market`. The controller is deployed separately, keeping miner initcode below EIP-3860's 49,152-byte limit.

Deployment order: gateway v2 (paused, designated operator), controller (immutable publisher = gateway), gateway bindController(controller, exact immutable-patched runtime hash), miner (controller authority), controller bindMiner(miner), independent verification, exact400M funding, separate founder arm. All deployments and bindings use the designated founder. Gateway binding rejects a controller already bound to a miner. No gateway proxy, generic executor, fund withdrawal or controller replacement exists.

The current financier can commission a deterministic FINANCIER category via controller commission(round,category). The miner spends its available IMD work budget on the official Intake. Budget accumulation is not job creation. Official callbacks record completion/failure but cannot choose reward recipients. Gateway-restricted admission binds the exact request/body/job before accepted contributions; snapshot locking and finalization enforce bounded period/deadline/replay rules. Equal per-agent shares aggregate by supported seat-owner wallet; holders claim on Robinhood at that address.

The supervised relay checks chain4663 Intake receipts and request bodies, official job records, canonical finalized Ethereum WorkRegistry commitments and exact report bytes. It joins accepted signals.agentId to submissions/seat token IDs, then original NFT ownership at the last Ethereum block at or before period end. NFT ownership alone proves no work. Code-bearing/unsupported owners stay in the denominator, with their shares quarantined. The on-chain contracts do not authenticate these cross-chain/API joins themselves.

Financier claimFincr(), outgoing fallback claimImd() and agent claim(roundId) are independent pull paths. Optional market execution is budget-bounded; failed attempts preserve accounting and can defer execution. PermanentV4Market has no principal-removal or upgrade path. Transaction-local spot limits do not establish fair value or eliminate MEV. The initial official pool and its service custody are separate from supplemental protocol liquidity and require real launch verification.
